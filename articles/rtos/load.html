Mesurer le temps de charge CPU

Le noyau Mk calcule à intervalle régulier le taux de charge CPU de toutes les tâches. Cet article décrit l'algorithme de calcul utilisé, ses limites et la méthodologie que doit mettre en œuvre une application pour récupérer le taux de charge CPU d'une tâche.

1. Principe

La mesure repose sur le timer système (SysTick). Ce timer est un compteur 24 bits descendant qui est rechargé à chaque tick du noyau.


Lors de chaque changement de contexte, le noyau lit la valeur du compteur et effectue une différence avec celle qu'il avait relevée lors du changement de contexte précédent. Cette différence représente la durée pendant laquelle la tâche courante a été exécutée. Elle est exprimée en périodes d'horloge du timer et est ajoutée au compteur de la tâche lors de chaque changement de contexte.


Le calcul des charges CPU est réalisé par la fonction mk_scheduler_load. Celle-ci est exécutée par le vecteur PendSV à chaque changement de contexte juste après la sauvegarde des registres de la tâche courante et avant l'élection de la prochaine tâche à exécuter.

2. Les registres de calcul

Les registres de calcul du temps de charge CPU sont regroupés dans la structure T_mkLoad de l'ordonnanceur et dans la structure T_mkTaskLoad de chaque tâche. Ces registres sont les suivants :


Structure Registre Description
scheduler load.timerRegister Valeur de rechargement du timer système. Elle est définie par l'utilisateur lors de l'appel des fonctions mk_start et mk_restart.
scheduler load.usTickRegister Valeur du timer système relevée lors du dernier changement de contexte.
scheduler load.usTickRegisterSum Durée écoulée depuis le début d'une fenêtre de calcul.
scheduler load.usTickRegisterLastSum Durée de la dernière fenêtre de calcul.
scheduler load.tickRegister Valeur du dernier tick de l'ordonnanceur mémorisé. Il permet de détecter un nouveau tick.
scheduler load.cycleRegister Nombre de ticks écoulés dans la fenêtre de calcul courante. Il évolue de 0 à K_MK_SCHEDULER_CPU_LOAD_RATE.
task load.value Durée d'exécution cumulée de la tâche sur la fenêtre de calcul en cours.
task load.lastValue Durée d'exécution de la tâche sur la dernière fenêtre de calcul.

3. Description de l'algorithme

Lors de chaque changement de contexte, la fonction mk_scheduler_load réalise les opérations suivantes :

  • ✔ Elle lit d'abord la valeur du timer système et la valeur du bit de débordement qui indique si le compteur a atteint la valeur 0 depuis la dernière lecture ou non.
  • ✔ Si le compteur a débordé, la valeur relevée au changement de contexte précédent est ajoutée à la tâche courante et le point de départ de la mesure est réinitialisé avec la valeur de rechargement du timer.
  • ✔ La fonction calcule ensuite la durée écoulée depuis le point de départ puis ajoute cette durée à la tâche courante et à la durée totale de la mesure.
  • ✔ Si un nouveau tick est détecté, le nombre de cycles dans la fenêtre de calcul est incrémenté.
  • ✔ Lorsque la fenêtre de calcul est terminée, c'est-à-dire lorsque K_MK_SCHEDULER_CPU_LOAD_RATE ticks se sont écoulés, les résultats sont publiés et une nouvelle mesure démarre.
  • ✔ La fonction mémorise alors la valeur du timer pour le prochain changement de contexte.

⚠️

L'algorithme ne détecte qu'un seul débordement entre deux changements de contexte. L'exception PendSV ne doit donc pas être retardée de plus d'un tick par des interruptions plus prioritaires.


L'algorithme ci-dessous est l'algorithme implémenté dans le noyau Mk pour calculer les taux de charge CPU : 


void mk_scheduler_load ( void )
{
   /* Lecture du timer système et du bit COUNTFLAG */
   uint32_t l_sysTickValue = systick_getCountValue ( );
   uint32_t l_countFlag = systick_getCountFlag ( );

   /* Si le timer a débordé depuis le dernier changement de contexte */
   if ( l_countFlag != 0 )
   {
      /* Ajout de la durée écoulée avant le débordement */
      g_mkScheduler.currentTask->load.value += g_mkScheduler.load.usTickRegister;
      g_mkScheduler.load.usTickRegisterSum += g_mkScheduler.load.usTickRegister;

      /* Le timer a été rechargé, le point de départ devient la valeur de rechargement */
      g_mkScheduler.load.usTickRegister = g_mkScheduler.load.timerRegister;
   }

   /* Durée écoulée depuis le point de départ */
   uint32_t l_elapsed = g_mkScheduler.load.usTickRegister - l_sysTickValue;
   g_mkScheduler.currentTask->load.value += l_elapsed;
   g_mkScheduler.load.usTickRegisterSum += l_elapsed;

   /* Détection d'un nouveau tick */
   if ( g_mkScheduler.tickRegister != g_mkScheduler.load.tickRegister )
   {
      g_mkScheduler.load.tickRegister += 1;
      g_mkScheduler.load.cycleRegister += 1;
   }

   /* Fin de la mesure : publication des résultats */
   if ( g_mkScheduler.load.cycleRegister == K_MK_SCHEDULER_CPU_LOAD_RATE )
   {
      g_mkScheduler.load.cycleRegister = 0;

      g_mkScheduler.load.usTickRegisterLastSum = g_mkScheduler.load.usTickRegisterSum;
      g_mkScheduler.load.usTickRegisterSum = 0;

      g_mkScheduler.idle.load.lastValue = g_mkScheduler.idle.load.value;
      g_mkScheduler.idle.load.value = 0;

      for ( uint32_t l_counter = 0 ; l_counter < K_MK_SCHEDULER_MAX_NUMBER_OF_TASKS ; l_counter++ )
      {
         g_mkTaskPool.task [ l_counter ].load.lastValue = g_mkTaskPool.task [ l_counter ].load.value;
         g_mkTaskPool.task [ l_counter ].load.value = 0;
      }
   }

   /* Mémorisation de la valeur du timer */
   g_mkScheduler.load.usTickRegister = l_sysTickValue;
}

4. Utilisation

Les durées sont accumulées dans les registres value des tâches pendant K_MK_SCHEDULER_CPU_LOAD_RATE ticks. À l'issue de cette période, les valeurs sont copiées dans les registres lastValue de chaque tâche puis réinitialisées pour débuter un nouveau cycle de calcul.


Le taux de charge d'une tâche est calculé à la demande par la fonction mk_task_getLoad. La formule suivante est utilisée : 


TC = ( task.load.lastValue * 100 ) / g_mkScheduler.load.usTickRegisterLastSum

Le dénominateur est la durée réellement mesurée et non la période théorique. Le calcul est réalisé avec des entiers (troncature).


L'extrait de code ci-dessous montre comment récupérer le taux de charge CPU d'une tâche : 


uint32_t l_load;

/* Taux de charge de la tâche courante */
l_result = mk_task_getLoad ( mk_task_getCurrent ( ), &l_load );

/* Taux de charge de la tâche de repos */
l_result |= mk_task_getLoad ( &g_mkScheduler.idle, &l_load );

Le taux de charge retourné est nul tant qu'une mesure complète n'a pas été réalisée, c'est-à-dire pendant les K_MK_SCHEDULER_CPU_LOAD_RATE premiers ticks suivant le démarrage du noyau ou suite à la création d'une tâche pendant une fenêtre de mesure.

5. Limitations

Le noyau ne relève la valeur du timer système qu'aux changements de contexte. Il ne mesure donc pas la durée consommée dans les vecteurs d'interruption.


⚠️

Le taux de charge des interruptions n'est pas pris en compte. Il est inclus dans le taux de charge des tâches qui s'exécutaient lorsqu'elles se sont déclenchées.


Le taux de charge d'une tâche est donc surestimé de la durée des interruptions qui l'ont préemptée. En outre, le taux de charge de la tâche de repos ne fournit pas exactement le taux d'utilisation du processeur.

6. Configuration

La période de la mesure peut être modifiée à l'aide de la définition suivante :

Définition Description Valeur
K_MK_SCHEDULER_CPU_LOAD_RATE Cette constante définit la durée d'une fenêtre de mesure en multiple d'un tick système. Elle doit être différente de 0. 1000

Avec un tick de 1 ms, la valeur par défaut produit un nouveau résultat toutes les secondes. Une période courte rend la mesure plus réactive alors qu'une période longue lisse les variations de charge.


Les durées sont stockées dans des registres 32 bits et le calcul du taux de charge multiplie la durée d'exécution de la tâche par 100. La durée d'une fenêtre de calcul doit donc être dimensionnée de manière à ne pas provoquer un débordement du calcul.
