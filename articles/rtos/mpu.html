Protéger son programme avec Mk

Mk offre un ensemble de mécanismes pour protéger un programme. Cet article présente la méthodologie à utiliser pour déclarer et placer ses variables en mémoire, créer des tâches privilégiées et gérer les erreurs de permissions.

1. Déclarer et protéger ses variables

Dans un programme informatique, les variables déclarées sont positionnée par défaut dans les sections .bss, .data et .rodata. Mk configure ces sections de la manière suivante dans le fichier d'édition de lien :

Section Contenu Mémoire MPU Privilégié / Non privilégié Exécution
.rodata Constantes FLASH_ITCM 2 RW / RO Autorisée
.bss Variables non initialisées privilégiées DTCM_RAM 3 RW / Aucun accès Interdite
.data Variables initialisées privilégiées DTCM_RAM 3 RW / Aucun accès Interdite

L'extrait de code ci-dessous montre un exemple de déclaration dans chacune de ces sections :



/* Déclaration d'une variable dans la section .rodata */
const uint32_t g_rodata = 0x12345678 ;

/* Déclaration d'une variable dans la section .data */
uint32_t g_data = 5 ;

/* Déclaration de 2 variables dans la section .bss */
uint32_t g_bss1 = 0 ;
uint32_t g_bss2;

/* Une tâche privilégiée */
void mk_task_privileged ( T_mkAddr p_param )
{
   /* Déclaration d'une variable statique dans la section .data */
   static uint32_t s_data = 6 ;
   
   /* Déclaration d'une variable dans la pile de la tâche privilégiée */ 
   uint32_t l_stack = 6 ;

   /* ... */
}

Du fait des attributs de la MPU (aucun accès autorisé pour .bss et .data), les tâches non privilégiées ne peuvent pas accéder à ces variables en lecture et en écriture. Elles doivent donc déclarer leurs variables avec un attribut spécifique afin de les localiser dans la bonne section :

Section Contenu Mémoire MPU Privilégié / Non privilégié Exécution
.mk_unprivileged_bss_memory Variables non initialisées non privilégiées SRAM1 4 RW / RW Interdite
.mk_unprivileged_data_memory Variables initialisées non privilégiées SRAM1 4 RW / RW Interdite

L'extrait de code ci-dessous montre une déclaration dans les sections non privilégiées :



/* Déclaration d'une variable dans la section .mk_unprivileged_data_memory */
K_MK_UNPRIVILEGED_DATA_MEMORY uint32_t g_data = 5 ;

/* Déclaration d'une variable dans la section .mk_unprivileged_bss_memory */
K_MK_UNPRIVILEGED_BSS_MEMORY uint32_t g_bss = 0 ;

/* Une tâche non privilégiée */
void mk_task_unprivileged ( T_mkAddr p_param )
{
   /* Déclaration d'une variable statique */ 
   /* dans la section .mk_unprivileged_data_memory */
   K_MK_UNPRIVILEGED_DATA_MEMORY static uint32_t s_data = 6 ;
    
   /* Déclaration d'une variable dans la pile de la tâche non privilégiée */ 
   uint32_t l_stack = 6 ;
     

   /* ... */
}

En addition, le noyau offre deux macros supplémentaires afin d'allouer un buffer DMA ou un bloc mémoire partiellement partagé (RW/RO) :

Section Contenu Mémoire MPU Privilégié / Non privilégié Exécution
.mk_privileged_dma_memory Données DMA privilégiées SRAM1 1 RW / Aucun accès Interdite
.mk_privileged_ro_memory Données privilégiées partagées en lecture SRAM2 6 RW / RO Interdite

À l'instar des sections de type .bss, ces zones mémoire sont initialisées à la valeur nulle par le code de démarrage. On les utilise de la manière suivante : 



/* Déclaration d'une variable dans la section .mk_privileged_dma_memory */
/* Les accès au cache sont désactivés pour conserver une cohérence entre le CPU et la DMA */
K_MK_PRIVILEGED_DMA_MEMORY uint32_t g_dmaBuf [ 512 ];

/* Déclaration d'une variable dans la section .mk_privileged_ro_memory */
/* Les tâches privilégiées peuvent lire et écrire dans cette variable */
/* Les tâches non privilégiées peuvent seulement lire */
K_MK_PRIVILEGED_RO_MEMORY uint32_t g_shared;

Lors de l'écriture d'un programme, il est important d'avoir conscience des régles ci-dessous :


⚠️

Une variable globale ou statique déclarée sans macro est placée dans les sections .bss ou .data. Elle est donc inaccessible aux tâches non privilégiées. Une tâche non privilégiée qui la manipule provoque une exception MemManage.


⚠️

Une variable locale déclarée dans une fonction est placée dans la pile de la tâche qui exécute cette fonction.


⚠️

Les sections .mk_unprivileged_bss_memory, .mk_privileged_ro_memory et .mk_privileged_dma_memory sont des sections initialisées à zéro. Un initialiseur non nul placé sur ces déclarations n'a aucun effet.


2. Création des tâches privilégiées

Une tâche privilégiée est créée en utilisant la fonction mk_task_create et en spécifiant l'attribut K_MK_TYPE_PRIVILEGED lors de la configuration de la structure T_mkTaskCtrlBlock. 



/* Déclaration du buffer où sera stockée la pile de la tâche */
/* Celui-ci est positionné dans une zone privilégiée */
K_MK_PRIVILEGED_BSS_MEMORY uint32_t g_privilegedStackBuf [ 512 ];

/* Une tâche privilégiée quelconque */
void mk_task_myPrivilegedTask ( T_mkAddr p_param )
{
   /* Déclaration de la variable de retour */
   T_mkCode l_result;

   /* Déclaration d'un pointeur de tâche */
   T_mkTask* l_task;

   /* Déclaration d'une structure contenant les informations de la stack */
   T_mkStack l_stack;

   /* Déclaration d'une structure contenant les informations de la tâche */
   T_mkTaskCtrlBlock l_taskCtrlBlock;

   /* Configuration de la structure l_stack avec les attributs de la pile */
   l_result = mk_stack_create ( &l_stack, K_MK_TYPE_DEFAULT, 
      g_privilegedStackBuf, 512 );

   /* Configuration de la structure l_taskCtrlBlock */
   /* Type : tâche privilégiée non flottante */
   /* Pour une tâche privilégiée flottante : K_MK_TYPE_FLOATING_PRIVILEGED */
   l_result |= mk_task_setTaskCtrlBlock ( &l_taskCtrlBlock,
      K_MK_TYPE_PRIVILEGED, K_MK_TASK_ID_MY_TASK,
      10, K_MK_NULL );

   /* Création de la tâche */
   /* Point d'entrée de la tâche : mk_task_privileged */
   /* Argument de la fonction : "Hello world !" */
   l_result |= mk_task_create ( &l_task, &l_stack, K_MK_NULL,
      &l_taskCtrlBlock, mk_task_privileged, ( T_mkAddr ) 
      "Hello world !" );
}

Une tâche privilégiée ne peut être créée que depuis une autre tâche privilégiée, un vecteur d'interruption ou depuis le programme principal. Lorsqu'une tâche privilégiée est créée, elle s'exécute avec le bit nPRIV positionné à 0, elle peut donc accéder à toutes les ressources du système sauf restriction spéciale imposée par la MPU.


💬

Les tâches privilégiées utilisent le pointeur de pile PSP. Leur contexte reste protégé par la MPU vis-à-vis des tâches non privilégiées.

3. Création des tâches non privilégiées

Une tâche non privilégiée peut être créée en spécifiant l'attribut K_MK_TYPE_DEFAULT. Elle s'exécute avec le bit nPRIV positionné à 1 et n'accède qu'aux ressources non privilégiées autorisées par la MPU.



/* Déclaration du buffer où sera stockée la pile de la tâche */
/* Celui-ci est positionné dans une zone non privilégiée */
K_MK_UNPRIVILEGED_BSS_MEMORY uint32_t g_unprivilegedStackBuf [ 512 ];

/* ... */

/* Une tâche non privilégiée quelconque */
void mk_task_myUnprivilegedTask ( T_mkAddr p_param )
{   
   /* ... */
   
   /* Configuration de la structure l_stack avec les attributs de la pile */
   l_result = mk_stack_create ( &l_stack, K_MK_TYPE_DEFAULT, 
      g_unprivilegedStackBuf, 512 );
      
   /* Configuration de la structure l_taskCtrlBlock */
   /* Type : tâche non privilégiée non flottante */
   /* Pour une tâche non privilégiée flottante : K_MK_TYPE_FLOATING */
   l_result = mk_task_setTaskCtrlBlock ( &l_taskCtrlBlock,
      K_MK_TYPE_DEFAULT, K_MK_TASK_ID_MY_TASK,
      10, K_MK_NULL );

   /* Si aucune erreur ne s'est produite */
   if ( l_result == K_MK_OK )
   {
      /* Création de la tâche */
      /* Point d'entrée de la tâche : mk_task_non_privileged */
      /* Argument de la fonction : "Hello world !" */
      l_result = mk_task_create ( &l_task, &l_stack, K_MK_NULL,
         &l_taskCtrlBlock, mk_task_unprivileged, ( T_mkAddr ) 
         "Hello world !" );
   }
}

Une tâche non privilégiée peut être créée par n'importe quel type de tâche, depuis un vecteur d'interruption ou encore depuis le programme principal.

4. Partager des données

Dans l'écosystème Mk, les boîtes de messages peuvent être utilisées pour partager des données entre les tâches.

Lorsqu'une donnée doit transité du monde privilégié au monde non privilégiée, une boite de messages doit être déclarée avec l'attribut K_MK_AREA_UNPROTECTED.

Avec cet attribut, le noyau autorise la tâche privilégié à manipuler la boite de messages.

L'extrait de code ci-dessous montre un exemple d'utilisation : 



/* Déclaration du buffer de la boite de messages */
/* Celui-ci doit obligatoirement être dans une zone non privilégiée */
K_MK_UNPRIVILEGED_BSS_MEMORY uint32_t l_mailBuf [ 512 ];

/* Déclaration d'un pointeur de boite de messages */
/* Celui-ci doit être accessible en lecture à la tâche non privilégiée */
K_MK_PRIVILEGED_RO_MEMORY T_mkMail* g_mail;

/* Code de la tâche privilégiée */
void mk_task_privileged ( T_mkAddr p_param )
{
   /* Déclaration de la variable de retour */
   T_mkCode l_result = K_MK_OK;

   /* Déclaration d'une structure de type T_mkPoolArea */
   /* Cette structure est utilisée pour créer la boite de messages */
   T_mkPoolArea l_area;

   /* Déclaration du message à transmettre à la tâche non privilégiée */
   uint32_t l_incommingMessage = 1;

   /* Suppression warning */
   ( void ) p_param;

   /* Création de la boite de messages */
   /* On crée 4 messages de 4 octets chacun */
   /* La boite n'est pas protégée, elle peut être utilisée par une tâche */
   /* non privilégiée */
   l_result = mk_pool_initArea ( &l_area, l_mailBuf, 512 );
   l_result |= mk_mail_create ( &g_mail, 
      K_MK_AREA_UNPROTECTED, &l_area, 1, 4 ); 

   /* Boucle pour toujours... */
   while ( 1 )
   {
      /* Ecriture d'un message dans la messagerie */
      l_result |= mk_mail_post ( g_mail, &l_incommingMessage, 
         K_MK_STATE_READY, K_MK_TASK_WAIT_FOREVER );

      /* Temporisation de la tâche */
      l_result |= mk_task_sleep ( 10 );            
   }

   /* Retour */
   return;
}

/* Code de la tâche non privilégiée */
void mk_task_unprivileged ( T_mkAddr p_param )
{
   /* Déclaration de la variable de retour */
   T_mkCode l_result = K_MK_OK;

   /* Déclaration de la variable où sera stocké le message reçu */
   uint32_t l_outcommingMessage = 0;

   /* Suppression warning */
   ( void ) p_param;

   /* Boucle pour toujours... */
   while ( 1 )
   {
      /* Récupération d'un message dans la messagerie */
      /* La variable l_message passe à 1 */
      l_result |= mk_mail_pend ( K_MK_NULL, g_mail, 
         &l_outcommingMessage, K_MK_TASK_WAIT_FOREVER );

      /* Temporisation de la tâche */
      l_result |= mk_task_sleep ( 10 );            
   }

   /* Retour */
   return;
}

Bien que la tâche non privilégiée puisse manipuler la boite, celle-ci reste protégée en écriture. La boite peut être créée depuis les deux types de tâches. Néanmoins, dans le cas d'un partage privilégié/non privilégiée, le buffer de la boite (l_mailBuf) et le message copié de la boite vers le buffer utilisateur (l_outcommingMessage) doivent être alloués dans une zone non privilégiée.


A reformuler :

Bien que les boites de messages soit sécurisées, une erreur de configuration peut ouvrir une brèche de sécurité. Lors de sa création, une boite de messages se voit spécifier une taille pour ses messages.

⚠️

Dans la situation où l'utilisateur déclare sa variable l_outcommingMessage dans une pile privilégiée avec une taille inférieure à la taille nominale de la boite alors le noyau viendra écraser la pile avec des données arbitraire.
