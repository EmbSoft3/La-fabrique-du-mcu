Allouer des blocs de taille fixe avec les Pools

Le module pool permet d'allouer des blocs mémoire de taille fixe. Cette page détaille le fonctionnement et l'utilisation des fonctions de ce module.

1. Synthèse des fonctions

Les fonctions de ce module sont déclarées dans le fichier mk_pool.h :

Fonction Description
mk_pool_initArea Initialise le buffer mémoire d'une pool.
mk_pool_create Crée une pool mémoire.
mk_pool_alloc Alloue un bloc mémoire de taille fixe dans une pool.
mk_pool_free Désalloue un bloc mémoire de taille fixe.
mk_pool_allocSafe Alloue un bloc mémoire de taille fixe dans une pool (thread safe).
mk_pool_freeSafe Désalloue un bloc mémoire de taille fixe (thread safe).
mk_pool_count Récupère le nombre de blocs disponibles dans une pool.
mk_pool_available Récupère l'adresse du prochain bloc disponible dans une pool.
mk_pool_delete Supprime une pool.

2. Fonctionnement

Une pool est construite à partir d'un buffer fourni par l'application. Ce buffer est découpé en plusieurs blocs de taille identique. Chaque bloc ainsi créé peut être alloué ou désalloué. La figure ci-dessous montre l'état initial d'une pool composée de 4 blocs mémoire :

Lors de l'initialisation, le noyau réalise le chaînage de l'ensemble des blocs en écrivant l'adresse du prochain bloc disponible dans l'en-tête de chaque bloc (ou la valeur null pour le dernier bloc).


💬

L'en-tête mesure 4 octets et se situe dans le premier mot de chaque bloc. Celle-ci n'existe que lorsque le bloc est dans la chaîne. Lors d'une allocation, l'application récupère l'intégralité du bloc et peut l'écraser. Il n'y a aucun surcoût mémoire.

Lorsqu'une allocation est réalisée, le noyau retire le premier bloc de la chaîne et le fournit à l'application. Le pointeur current est alors actualisé pour pointer sur le prochain bloc disponible. La figure ci-dessous montre l'état de la pool après deux allocations successives :

Les blocs 3 et 4 ne font plus partie de la chaîne et la pool ne possède plus que deux blocs.

Lorsqu'une désallocation est réalisée, le noyau effectue l'opération inverse en ajoutant un nouvel élément à la chaîne. La figure ci-dessous montre l'état de la pool lorsque les blocs 4 puis 3 sont désalloués :

Lors d'une désallocation, le pointeur current est modifié pour pointer systématiquement sur le dernier bloc entré. La pool fonctionne donc selon un algorithme de type LIFO, c'est-à-dire que le dernier bloc désalloué sera le prochain bloc alloué.

Lorsque l'ensemble des blocs a été alloué, le pointeur current devient nul. L'application doit donc attendre une désallocation avant de pouvoir allouer un nouveau bloc.


Un gestionnaire d'allocation de taille fixe possède beaucoup d'avantages :

  • ✔Une pool fournit toujours la même taille de bloc, le phénomène de fragmentation ne peut donc pas se produire.
  • ✔Elle n'alloue pas dans le tas (heap) mais dans son buffer applicatif.
  • ✔Ses durées d'allocation et de désallocation sont fixes, elle est donc déterministe car son architecture ne nécessite aucune recherche pour effectuer une opération.

Néanmoins, son principal défaut est qu'elle ne peut allouer que des blocs de taille fixe. Il est donc nécessaire de créer une pool par taille de données à allouer.

3. Utilisation

La création d'une pool s'effectue à partir des fonctions mk_pool_initArea et mk_pool_create. L'exemple ci-dessous présente l'initialisation d'un gestionnaire de taille fixe de 12 blocs :


/* Déclaration du buffer de la pool */
/* Sa taille est de 12 * 8 mots soit 96 mots */
K_MK_UNPRIVILEGED_BSS_MEMORY uint32_t g_poolBuf [ 96 ];

/* Déclaration d'un pointeur de pool */
K_MK_UNPRIVILEGED_BSS_MEMORY T_mkPool* g_pool;

/* Une tâche quelconque */
void mk_task ( void )
{
   /* Déclaration de la variable de retour */
   T_mkCode l_result = K_MK_OK;

   /* Déclaration d'une structure contenant les caractéristiques du buffer */
   T_mkPoolArea l_area = { };

   /* Initialisation du buffer de la pool */  
   /* La taille est exprimée en mots 32 bits */  
   l_result = mk_pool_initArea ( &l_area, g_poolBuf, 96 ); 

   /* Si aucune erreur ne s'est produite */
   if ( l_result == K_MK_OK )
   {
      /* Création de la pool */
      /* Elle est accessible aux tâches privilégiées et non privilégiées */
      /* Taille : 12 blocs de 8 mots 32 bits chacun */
      l_result = mk_pool_create ( &l_area, &g_pool, 
         K_MK_AREA_UNPROTECTED, 8, 12 );
   }

   /* ... */
   for ( ;; ) ;
}

Suite à sa création, les blocs de la pool peuvent être alloués ou désalloués au sein d'une même tâche en utilisant les fonctions mk_pool_alloc, mk_pool_free ou entre deux tâches en utilisant les fonctions mk_pool_allocSafe ou mk_pool_freeSafe.

Les fonctions mk_pool_alloc et mk_pool_free ne sont pas protégées contre les accès concurents, elle ne réalise aucun appel système et de ce fait sont plus rapide que les précédente.

4. API

4.1. La fonction mk_pool_initArea()

Cette fonction initialise une zone mémoire dédiée à l'allocation dynamique.


Prototype :


T_mkCode mk_pool_initArea ( 
   T_mkPoolArea* p_mkArea, T_mkAddr p_mkBuf, uint32_t p_mkSize );

Paramètres :

  • p_mkArea [out]

    Adresse d'une structure de type T_mkPoolArea.


  • p_mkBuf [in]

    Adresse de base de la zone mémoire dédiée à l'allocation dynamique.


  • p_mkSize [in]

    Taille de la zone mémoire dédiée à l'allocation dynamique (en multiple de mots 32 bits).

Retour :

  • K_MK_OK : les attributs de la zone mémoire ont été initialisés.
  • K_MK_ERROR_PARAM : les attributs de la zone mémoire n'ont pas été initialisés car au moins un paramètre est invalide.
4.2. La fonction mk_pool_create()

Cette fonction initialise un gestionnaire d'allocation dynamique de taille fixe dans la zone mémoire définie par la structure T_mkPoolArea.


Prototype :


T_mkCode mk_pool_create ( T_mkPoolArea* p_mkArea, T_mkPool** p_mkPool, 
   uint32_t p_mkAreaType, uint32_t p_mkSize, uint32_t p_mkCount );

Paramètres :

  • p_mkArea [in]

    Adresse d'une structure de type T_mkPoolArea.


  • p_mkPool [out]

    Adresse d'un pointeur de type T_mkPool*.


  • p_mkAreaType [in]

    Type de la zone mémoire. Les valeurs possibles sont les suivantes :

    • K_MK_AREA_PROTECTED : le gestionnaire est protégé des appels système de type non privilégié.
    • K_MK_AREA_UNPROTECTED : le gestionnaire n'est pas protégé des appels système de type non privilégié.

  • p_mkSize [in]

    Taille des blocs mémoire (en multiple de mots 32 bits).


  • p_mkCount [in]

    Nombre de blocs mémoire.

Retour :

  • K_MK_OK : le gestionnaire d'allocation dynamique a été initialisé.
  • K_MK_ERROR_PARAM : le gestionnaire d'allocation dynamique n'a pas été initialisé car au moins un paramètre est invalide.
  • K_MK_ERROR_MALLOC : le gestionnaire d'allocation dynamique n'a pas été initialisé car la taille de la zone mémoire définie par la structure T_mkPoolArea est insuffisante.
  • K_MK_ERROR_ISR : le gestionnaire d'allocation dynamique n'a pas été initialisé car cette fonction a été exécutée depuis un vecteur d'interruption.

Note :

  • Cette fonction ne peut pas être exécutée dans un vecteur d'interruption.
  • La mémoire réservée par cette fonction à partir de la structure T_mkPoolArea ne peut pas être désallouée.
4.3. La fonction mk_pool_alloc()

Cette fonction alloue un bloc de taille fixe dans un gestionnaire d'allocation dynamique.


Prototype :


T_mkAddr mk_pool_alloc ( T_mkPool* p_mkPool, uint32_t p_mkClear );

Paramètres :

  • p_mkPool [in, out]

    Adresse d'une structure de type T_mkPool.


  • p_mkClear [in]

    Ce paramètre indique si le bloc alloué doit être initialisé à zéro (K_MK_POOL_CLEAR) ou non (K_MK_POOL_NO_CLEAR).

Retour :

  • L'adresse du bloc de taille fixe alloué ou la valeur K_MK_NULL si aucun bloc n'est disponible ou si un paramètre est invalide.

Note :

  • Cette fonction n'est pas de type « thread safe ». Pour une utilisation concurrente, la fonction mk_pool_allocSafe doit être utilisée.
4.4. La fonction mk_pool_free()

Cette fonction désalloue un bloc de taille fixe.


Prototype :


T_mkCode mk_pool_free ( T_mkPool* p_mkPool, T_mkAddr p_mkAddr );

Paramètres :

  • p_mkPool [in, out]

    Adresse d'une structure de type T_mkPool.


  • p_mkAddr [in]

    Adresse du bloc de taille fixe à désallouer.

Retour :

  • K_MK_OK : le bloc de taille fixe a été désalloué.
  • K_MK_ERROR_PARAM : le bloc de taille fixe n'a pas été désalloué car au moins un paramètre est invalide.

Note :

  • Le bloc de taille fixe doit être désalloué dans le gestionnaire d'allocation de type T_mkPool d'où il est originaire.
  • Cette fonction n'est pas de type « thread safe ». Pour une utilisation concurrente, la fonction mk_pool_freeSafe doit être utilisée.
4.5. La fonction mk_pool_allocSafe()

Cette fonction alloue un bloc de taille fixe dans un gestionnaire d'allocation dynamique. Elle peut bloquer la tâche appelante jusqu'à la libération d'un bloc.


Prototype :


T_mkCode mk_pool_allocSafe ( T_mkPool* p_mkPool, T_mkAddr* p_mkAddr, 
   uint32_t p_mkClear, uint32_t p_mkTick );

Paramètres :

  • p_mkPool [in, out]

    Adresse d'une structure de type T_mkPool.


  • p_mkAddr [out]

    Adresse du bloc de taille fixe alloué ou valeur K_MK_NULL si l'allocation a échoué.


  • p_mkClear [in]

    Ce paramètre indique si le bloc alloué doit être initialisé à zéro (K_MK_POOL_CLEAR) ou non (K_MK_POOL_NO_CLEAR).


  • p_mkTick [in]

    Durée maximale de blocage de la tâche. Les valeurs possibles sont les suivantes :

    • 0x0 : la fonction retourne immédiatement si aucun bloc n'est disponible.
    • 0x1 à 0xFFFFFFFE : la tâche est bloquée pendant la durée spécifiée (en multiple de tick) tant qu'aucun bloc n'est disponible.
    • 0xFFFFFFFF (K_MK_TASK_WAIT_FOREVER) : la tâche est bloquée tant qu'aucun bloc n'est disponible.

Retour :

  • K_MK_OK : le bloc de taille fixe a été alloué.
  • K_MK_ERROR_PARAM : le bloc de taille fixe n'a pas été alloué car au moins un paramètre est invalide.
  • K_MK_ERROR_MALLOC : le bloc de taille fixe n'a pas été alloué car aucun bloc n'était disponible dans le délai imparti.
  • K_MK_ERROR_ISR : le bloc de taille fixe n'a pas été alloué car cette fonction a été exécutée depuis un vecteur d'interruption.
  • K_MK_ERROR_RIGHT : le bloc de taille fixe n'a pas été alloué car une tâche de type non privilégié ne peut pas utiliser un objet de type T_mkPool protégé.

Note :

  • Cette fonction ne peut pas être exécutée dans un vecteur d'interruption.
4.6. La fonction mk_pool_freeSafe()

Cette fonction désalloue un bloc de taille fixe.


Prototype :


T_mkCode mk_pool_freeSafe ( T_mkPool* p_mkPool, T_mkAddr p_mkAddr );

Paramètres :

  • p_mkPool [in, out]

    Adresse d'une structure de type T_mkPool.


  • p_mkAddr [in]

    Adresse du bloc de taille fixe à désallouer.

Retour :

  • K_MK_OK : le bloc de taille fixe a été désalloué.
  • K_MK_ERROR_PARAM : le bloc de taille fixe n'a pas été désalloué car au moins un paramètre est invalide.
  • K_MK_ERROR_ISR : le bloc de taille fixe n'a pas été désalloué car cette fonction a été exécutée depuis un vecteur d'interruption.
  • K_MK_ERROR_RIGHT : le bloc de taille fixe n'a pas été désalloué car une tâche de type non privilégié ne peut pas utiliser un objet de type T_mkPool protégé.

Note :

  • Cette fonction ne peut pas être exécutée dans un vecteur d'interruption.
  • Le bloc de taille fixe doit être désalloué dans le gestionnaire d'allocation de type T_mkPool d'où il est originaire.
4.7. La fonction mk_pool_count()

Cette fonction retourne le nombre de blocs de taille fixe disponibles dans un gestionnaire d'allocation dynamique.


Prototype :


T_mkCode mk_pool_count ( T_mkPool* p_mkPool, uint32_t* p_mkCount );

Paramètres :

  • p_mkPool [in]

    Adresse d'une structure de type T_mkPool.


  • p_mkCount [out]

    Nombre de blocs mémoire disponibles.

Retour :

  • K_MK_OK : le nombre de blocs de taille fixe a été récupéré.
  • K_MK_ERROR_PARAM : le nombre de blocs de taille fixe n'a pas été récupéré car au moins un paramètre est invalide.
  • K_MK_ERROR_ISR : le nombre de blocs de taille fixe n'a pas été récupéré car cette fonction a été exécutée depuis un vecteur d'interruption.

Note :

  • Cette fonction ne peut pas être exécutée dans un vecteur d'interruption.
4.8. La fonction mk_pool_available()

Cette fonction retourne l'adresse du prochain bloc de taille fixe disponible, sans l'allouer.


Prototype :


T_mkAddr mk_pool_available ( T_mkPool* p_mkPool );

Paramètres :

  • p_mkPool [in]

    Adresse d'une structure de type T_mkPool.

Retour :

  • L'adresse du prochain bloc de taille fixe ou la valeur K_MK_NULL si aucun bloc n'est disponible.
4.9. La fonction mk_pool_delete()

Cette fonction supprime un gestionnaire d'allocation dynamique.


Prototype :


T_mkCode mk_pool_delete ( T_mkPool* p_mkPool );

Paramètres :

  • p_mkPool [in, out]

    Adresse d'une structure de type T_mkPool.

Retour :

  • K_MK_OK : le gestionnaire d'allocation dynamique a été détruit.
  • K_MK_ERROR_PARAM : le gestionnaire d'allocation dynamique n'a pas été détruit car le paramètre est invalide.
  • K_MK_ERROR_ISR : le gestionnaire d'allocation dynamique n'a pas été détruit car cette fonction a été exécutée depuis un vecteur d'interruption.
  • K_MK_ERROR_RIGHT : le gestionnaire d'allocation dynamique n'a pas été détruit car une tâche de type non privilégié ne peut pas utiliser un objet de type T_mkPool protégé.
